# Validation retention

Completed review captures, logs, attempt reports and cleanup reports are temporary.
Delete them after inspecting the results and recording useful conclusions in the
existing project documentation. Keep evidence for unresolved failures until the
failure is resolved. Generated outputs are ignored by default; the exact files
retained here are listed as exceptions in the repository `.gitignore`.

The retained JSON files are inputs to current tools or preservation baselines:

| Files | Purpose |
| --- | --- |
| `construction-stages.json`, `energy-construction-source.json` | Construction checks and native stage compilation. |
| `controller-detail-loop-01/source.json`, `reactor-exterior-loop-01/source.json`, `energy-construction-update/protected-source.json`, `native-texture-detail/source.json` | Accepted geometry fingerprints used by modelling audits. |
| `reactor-texture-lod-loop/*-protected.json` | Main-mesh and collision baselines for derived-model audits. |
| `thermal-concepts/battery-reference.json`, `reactor-reference.json`, `protected-production.json` | Reference reconstruction and source-preservation checks used by retained concept tools. |
| `thermal-models/models.json`, `native-source-scenes.json`, `native-export-sources.json` | Model contracts, source/export mappings and the incremental export ledger. |
| `thermal-models/protected-sources.json`, `tight-fit-before-interfaces.json` | Source fingerprints and socket dimensions used by thermal geometry audits. |
| `thermal-models/internal-pipes-baseline.json`, `internal-pipes-preserved.json` | Accepted reactor internal-pipe baseline and preservation evidence required by delivery checks. |
| `thermal-models/flow-review-states.json` | Compiled runtime samples read by the Blender flow preview; regenerated by `tools/check_thermal_runtime.py`. |
| `thermal-models/native-export.json`, `native-motion.json`, `release-manifest.json` | Current native export, animation and package manifests used by delivery checks and incremental installation. |

`thermal-models/delivery-check.json` is the single retained delivery summary.
Refresh it after relevant changes; do not accumulate dated copies. A retained
report only covers its recorded checks and does not establish an in-game test.

Do not regenerate a preservation baseline from a changed asset merely to pass
an audit. Inspect report readers and writers before changing retention rules;
some files named like reports are required build inputs. Documentation links alone
do not make an old report a build dependency.

After cleanup, run these commands from the repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 ArcanePower/tools/check_thermal_delivery.py
git diff --check
```

The delivery check recreates `block-catalog.json`; inspect it and remove it again
once the check succeeds. Use the same approach for other disposable outputs
regenerated during verification.

The mandatory modelling cleanup workflow is in [assets/AGENTS.md](../assets/AGENTS.md).
